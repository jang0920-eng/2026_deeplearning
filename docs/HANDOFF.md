# 2. 환경 함정 (실제로 당했던 것들)

- Colab 이미지가 Python 3.13으로 바뀌면서 nvidia 라이브러리가 기본 포함되지 않음.

  `ldd`로 부족한 라이브러리를 찾아 pip 설치하고 `LD_LIBRARY_PATH`에
  `site-packages/nvidia/*/lib`를 추가하는 셀이다.
- gnina 바이너리는 `https://api.github.com/repos/gnina/gnina/releases`에서
  **cuda12 빌드**를 받아 Drive(`cdk2/tools/gnina`)에 캐시해 재다운로드를 피한다.
- 세션 첫 도킹은 CNN 모델 로딩 때문에 비정상적으로 느리다(~180초). **속도 측정에서 제외할 것.**

### Colab 노트북 저장
- GitHub에서 연 Colab 노트북(`colab.research.google.com/github/...`)은 **저장되지 않는다.**
  실행 결과를 남기려면 `파일 → 드라이브에 사본 저장` 후 실행.
- GitHub 열기에는 **캐시가 있어** 최신 커밋이 늦게 반영될 수 있다.
  푸시했는데 셀 내용이 옛날 것이면 캐시 문제다. 새 셀에 코드를 직접 붙여넣는 게 빠르다.

### Colab 런타임 끊김
- 끊기면 메모리 변수가 전부 날아간다(`import subprocess`까지도).
- 복구 셀은 이전 셀 상태를 가정하지 말고 **CSV/저장 파일에서 다시 읽도록** 작성할 것.

# 3. 확정된 결정 (바꾸지 말 것)

### 타겟
- **단백질: CDK2** — ChEMBL `CHEMBL301`, Homo sapiens, SINGLE PROTEIN
- **질환: CDK4/6 억제제 내성 HR+/HER2− 전이성 유방암**
  - 근거: CDK4/6 억제제가 표준 치료이나 대부분 내성을 획득하고, 그 기전이 cyclin E-CDK2 활성화.
  - "유방암 치료제"가 아니라 **"내성 극복"**으로 틀을 잡았다.
    이미 있는 CDK4/6 억제제로 충분하지 않냐는 반박을 막기 위함.

### 단백질 구조
- **PDB 3RPR** (1.75 Å, 리간드 25Z, chain A 단독)
- **도킹 박스: center (92.37, 80.29, −47.95), size 16.1 × 15.8 × 16.5** — 현행 유지 확정
- 탈락 구조: 6INL(결손 148–162가 포켓 잔기 Asp145 직후), 5L2W(2.80 Å, cyclin E 동반)
- 5L2W의 dinaciclib은 임상 화합물이라 **최종 후보 비교용으로 보관**
- 3RPR의 결손 구간 37–44는 포켓 잔기로부터 서열상 4잔기 거리 (문제 없음)

### 채택 모델
- **활성 예측: Morgan fingerprint + Random Forest** (PR-AUC 0.881로 1위)
- **도킹: GNINA, CNN rescore 켬, exhaustiveness 8, 박스 16 Å**

1. hERG / AMES / DILI 가 **승인 약물 분포 백분위 > 90** 이면 탈락 (80/90/95 민감도 함께 보고)
2. 통과 분자를 4단계 도킹 순위(`rank_mean`)로 **그대로** 정렬 — ADMET 에 가중치를 주지 않는다
3. 상위 30개. 통과가 30 미만이면 문턱값을 완화하지 않고 그 수를 그대로 보고한다

⚠ **확률 0.5 를 쓰지 않는다.** 승인 약물 2,845개에서 p > 0.5 인 비율이
DILI 44.3% / hERG 37.2% / AMES 20.9% 라 안전성 기준이 되지 못한다 (실측).

⚠ **BBB 는 높을 필요가 없다.** 적응증이 HR+/HER2− 유방암이므로 뇌가 표적 장기가 아니다.
"BBB 가 낮아서 나쁘다"고 쓰지 않는다.

시험 실행으로 스크립트 동작은 확인했다 (5개, 백분위 기준에서 4개 통과).

# 6. 과거에 겪은 문제와 해결 (같은 실수 반복 방지)

### 양수 도킹 점수(+1.10)의 원인 — 박스가 아니라 구조 생성
처음에 `CHEMBL271182`의 Vina 점수가 +1.10으로 나와 **박스가 작아서라고 추정**했다.
16/20/24 Å으로 비교해보니 차이가 0.13 kcal/mol뿐이라 **그 가설은 기각**됐다.

진짜 원인은 `02_gnina_speed_test.ipynb` 셀 5에서
- ETKDG 난수 시드를 고정하지 않았고
- MMFF 최적화가 기본 200회에 수렴 확인도 없었다

→ 뒤틀린 3D 구조가 만들어져 단백질과 충돌한 것.
→ 5장 C의 수정 코드를 반드시 적용.

**이 과정 자체가 보고서 소재다**: 추정으로 바꾸지 않고 실측으로 확인했다.

### RMSD 계산 함수
`GetBestRMS`는 두 분자를 **정렬한 뒤** 재므로 도킹 검증에 부적합.
`CalcRMS`는 정렬 없이 대칭만 고려 → 이쪽을 써야 한다.

# 8. 보고서에 쓸 거리 (배점별)

### 배점 1 — 모델 활용 다양성 / 자원 제약 고려 (30점)
- **CNN 채점 비용 ≈ 0, 병목은 CPU 탐색** — 실측 기반 설정 결정
- **도킹 3,000 → 1,000 축소** — 자원 한계를 인지하고 깔때기 재설계
- **Morgan > ChemBERTa** — 소규모·불균형·화학적으로 뭉친 데이터에서 지문+트리가 강하다
- **10M-MTR > 77M-MLM** — 두 모델은 구조가 완전히 동일(hidden 384, layer 3, head 12,
  vocab 600, 3.43M)하고 사전학습 방식·데이터 규모만 다르다. 구조가 통제돼 있어
  차이를 objective 탓으로 돌릴 수 있다. 사전학습 데이터 양(7,700만)보다 학습 목표가 중요했던 사례.
  → "문헌 보고 골랐다"가 아니라 **"문헌 보고 고른 뒤 같은 split에서 검증했다"**
- **GNINA Conv3d 원리** — W3 내용(`(N, 28, 48, 48, 48)`) 설명
- ✅ **Chemprop D-MPNN 추가 완료 (11/14)** — **지문 / 트랜스포머 / 그래프 세 계열 비교**가 됐다.
  PR-AUC: Morgan+RF 0.8807 > ChemBERTa-10M-MTR+RF 0.8637 > **Chemprop D-MPNN 0.8577**.
  순위가 표현력 순서와 반대다. 데이터 2,721개 규모에서는 표현을 학습할 데이터가 부족하다.
  같은 scaffold split, 같은 `eval_utils`, 시드 42, 격자 4개(CPU 제약), 886초.
  → `scripts/12_chemprop_compare.py`, `experiment/12_chemprop/`
- ✅ **ADMET 기준을 실측으로 바로잡았다 (11/14)** — 확률 0.5 로 자르면 **승인 약물 2,845개 중
  DILI 44.3% / hERG 37.2% / AMES 20.9% 가 탈락한다.** 기준을 승인 약물 분포 백분위 > 90 으로
  바꾸고 80/90/95 민감도를 함께 보고한다. "지표를 그대로 쓰지 않고 적용 조건을 검토한" 두 번째 사례.

- 진행 상황은 매 작업 세션 후 갱신한다 (날짜, 정확한 수치, 결정 이유, 다음 단계)
- 생성된 파일은 세션이 끝나면 사라지므로 **받는 즉시 저장**
- 모델은 revision(commit)을 고정해서 받는다
- 추정으로 결론 내리지 말고 실측으로 확인한다 (6장 사례)
