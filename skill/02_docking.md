## 1. 도킹 도구

| 항목 | 값 |
|---|---|
| 도구 | GNINA v1.3.3 (master:6fe1ce2, Built Jun 30 2026) |
| 설치 | conda 대신 GitHub 릴리스 바이너리, Google Drive 에 저장해 세션마다 재사용 |
| 실행 환경 | Google Colab 무료, Tesla T4 GPU, vCPU 2코어 |
| 설정 | exhaustiveness 8, num_modes 9, seed 1, CNN rescore 켬 |

### GNINA 가 하는 일 (W3 수업 내용과의 연결)
GNINA 는 Vina 계열의 도킹 탐색으로 결합 자세(pose)를 만든 뒤,
그 자세를 **3D CNN 으로 다시 채점**한다.

- 단백질과 리간드의 원자를 3차원 격자(voxel)에 담는다
- 2D 이미지의 `(N, C, H, W)` 에 대응하는 `(N, C, D, H, W)` 형태가 된다
- Def2018 설정의 입력은 `(N, 28, 48, 48, 48)` — 28은 원자 종류 등 channel, 48³은 공간 격자
- `Conv2d` 가 3×3 = 9개 위치를 보는 반면 `Conv3d` 는 3×3×3 = 27개 위치를 본다.
  결합은 앞뒤 방향을 포함한 3차원 배치가 중요하므로 Conv3d 가 필요하다
- 흐름: `3D molecular grid → Conv3d → ReLU → Pool3d → pose / affinity heads`

출력 점수는 두 가지다.
- `minimizedAffinity` — Vina 계열 점수 (kcal/mol, 음수일수록 결합에 유리)
- `CNNscore`, `CNNaffinity` — CNN 이 매긴 점수

## 2. 단백질 구조와 도킹 박스

| 항목 | 값 |
|---|---|
| PDB | **3RPR** (해상도 1.75 Å, chain A 단독, 리간드 25Z) |
| 전처리 | 물 217개 제거, 리간드 25Z 분리, pH 7.4 에서 수소 부가 (OpenBabel) |
| 박스 중심 | (92.37, 80.29, −47.95) |
| 박스 크기 | 16.1 × 15.8 × 16.5 Å |

### 구조 선정 근거
- **3RPR 채택**: 1.75 Å 로 해상도가 좋고, chain A 단독이라 불필요한 복잡도가 없다
- **6INL 탈락**: 결손 구간 148–162 가 포켓 잔기 Asp145 바로 뒤에 있어 결합 부위 신뢰도가 낮다
- **5L2W 탈락**: 해상도 2.80 Å 로 부족하고 cyclin E 가 동반되어 있다.
  다만 결합된 dinaciclib 이 임상 화합물이므로 최종 후보와의 비교 대상으로 보관한다
- 한계: 3RPR 에도 결손 구간 37–44 가 있으며, 포켓 잔기로부터 서열상 4잔기 거리다

## 3. 속도 실측 — 계산 자원 제약을 수치로 확인

리간드 20개(중원자 17~31개)로 측정했다.

| 설정 | 1개당 (중앙값) | 3,000개 환산 |
|---|---|---|
| A. CNN rescore 켬 | **59.0초** (평균 60.6초) | 49.2시간 |
| B. CNN 끔 (Vina 점수만) | 60.6초 | 50.5시간 |

- 첫 실행은 CNN 모델 로딩을 포함해 182.4초가 걸려 계산에서 제외했다
- 도킹 점수 범위: −9.92 ~ +1.10 kcal/mol

### 결론 1 — CNN 채점은 켜 둔다
A 와 B 가 오차 범위 안에서 같다. **CNN 채점의 추가 비용이 사실상 0이다.**
병목은 CNN 이 아니라 CPU 에서 수행되는 도킹 탐색(Monte Carlo)이며,
무료 Colab 은 vCPU 가 2코어뿐이라 GPU 성능과 무관하게 여기서 제한된다.
비용이 없으면서 CNNscore 라는 독립적인 지표를 하나 더 얻으므로 켜 둔다.

### 결론 2 — 도킹 대상을 3,000개에서 1,000개로 줄인다
실측 59초/개를 적용하면 3,000개는 약 49시간이다.
세션이 수시로 끊기는 무료 Colab 에서는 현실성이 없다.
1,000개면 약 15시간이라 나흘에 분할 처리할 수 있다.
줄어든 만큼은 앞단 ML 활성 예측의 통과 기준을 높여 보완한다.

### 결론 3 — 물리화학 필터에 lead-like 조건을 넣는다
회전결합 ≤ 7, MW ≤ 450.
도킹 소요 시간은 리간드의 회전결합 수에 비례해 늘어나므로 평균 도킹 시간이 내려간다.
동시에 신약 개발 관점에서도 타당하다. 최적화 과정에서 분자량이 증가하는 경향을 고려하면
출발 물질은 lead-like 영역에 두는 편이 유리하다.
계산 제약과 화학적 타당성이 같은 방향을 가리킨 선택이다.

## 4. 도킹 검증 (redocking) — **합격**

결정 구조에서 리간드 25Z 를 떼어낸 뒤 같은 자리에 다시 도킹해,
원래의 결합 자세를 재현하는지 확인했다. 두 가지 방식으로 수행했다.

| 검증 | 입력 | top-pose RMSD | 9개 pose 중 최소 | 판정 |
|---|---|---|---|---|
| A | 결정 좌표를 그대로 입력 | **0.60 Å** | 0.60 Å | 합격 |
| B | SMILES 에서 3D 구조를 새로 생성해 입력 | **0.56 Å** | 0.56 Å | 합격 |

- 판정 기준 2.0 Å. 두 방식 모두 크게 밑돈다
- 25Z 도킹 점수 −9.94 kcal/mol, CNNscore 0.993
- 소요 시간 A 78초, B 67초

### B 를 추가한 이유
A 만으로는 "출발 구조를 알려 줬으니 맞힌 것 아니냐"는 반론이 가능하다.
B 는 SMILES 에서 ETKDG 로 3D 구조를 새로 만들어 넣어 결정 좌표 정보를 완전히 지운다.
그럼에도 0.56 Å 로 재현했으므로 도킹 설정의 타당성 근거가 더 강하다.
B 가 A 보다 오히려 좋았다.

### 점수 1위 pose 가 RMSD 도 가장 낮았다
탐색과 점수 함수가 같은 답을 가리켰다는 뜻이다.
1,000개 도킹에서 상위 점수를 신뢰할 근거가 된다.

### RMSD 계산 방법
`rdMolAlign.CalcRMS` 를 사용했다. 대칭을 고려하되 **두 분자를 정렬하지 않고**
제자리에서 계산한다. `GetBestRMS` 는 분자를 정렬한 뒤 재므로 값이 작게 나와
도킹 검증에는 부적합하다. 중원자만 사용했다.

결정 리간드가 PDB 형식이라 결합 차수 정보가 없는 문제는,
RCSB 의 25Z ideal SDF 를 template 으로 써서 결합 차수를 부여해 해결했다.

## 5. 박스 크기 점검 — 현행 16 Å 유지

속도 측정 20개 중 `CHEMBL271182` 하나가 Vina **+1.10 kcal/mol** 로 나왔다.
양수는 결합이 성립하지 않았음을 뜻한다.
처음에는 분자가 박스를 벗어난 것으로 추정하고, 세 가지 박스로 다시 도킹해 확인했다.

| 박스 | Vina | CNNscore |
|---|---|---|
| 16 Å (현행) | **−8.80** | 0.846 |
| 20 Å | −8.93 | 0.787 |
| 24 Å | −8.91 | 0.867 |

- 해당 분자: 중원자 24개, 최대 축 길이 14.3 Å, pActivity 7.68 (활성 화합물)
- **같은 16 Å 박스에서 음수가 나왔고, 세 박스의 차이는 0.13 kcal/mol 로 사실상 없다**
- → 박스 크기는 원인이 아니었다. 박스는 현행대로 유지한다

### 진짜 원인 — 리간드 3D 구조 생성
속도 측정 노트북의 리간드 준비 코드에 두 가지 결함이 있었다.

1. **난수 시드를 고정하지 않았다.** `ETKDGv3()` 의 기본값은 매번 다른 구조를 만든다
2. **MMFF 최적화가 기본 200회이고 수렴 여부를 확인하지 않았다.**
   수렴 실패 시 1을 반환하는데 그 값을 버리고 있었다

그때 이 분자에 뒤틀린 구조가 만들어졌고, 포켓 어디에 놓아도 충돌이 나
양수 점수가 된 것이다. 검증 노트북은 `randomSeed=7`, `maxIters=2000` 으로
정상 구조를 만들었고 −8.80 이 나왔다.

본 도킹에서는 시드를 고정하고 최적화 반복을 늘리며 수렴을 확인하도록 수정한다.
시드 고정은 결과의 재현성을 확보하기 위한 조치이기도 하다.

### 이 과정 자체가 서술 대상
양수 점수를 박스 탓으로 **추정**했으나, 설정을 바꾸기 전에 세 가지 박스를 실제로
비교해 그 가설을 기각하고 진짜 원인을 찾았다.
추정으로 설정을 바꾸지 않고 실측으로 확인한 절차다.

## 7. 표현 주의 (보고서 작성 시 반드시 지킬 것)

- 도킹 점수는 **실험으로 검증된 결합 친화도가 아니다**
- 새 후보에 대해서는 **순위만** 산출한다. 결합 친화도를 예측했다고 쓰지 않는다
- "hit" 이라는 표현을 쓰지 않는다 (hit = 실험으로 활성이 확인된 분자)
- redocking 이 통과했다는 것은 **도킹 설정이 알려진 결합 자세를 재현했다**는 뜻이지,
  새 화합물의 결합을 보장한다는 뜻이 아니다
- 25Z 는 3RPR 의 공결정 리간드이므로, 그 자세를 재현한 것은
  "이미 답이 있는 문제를 푼 것"에 가깝다는 한계를 함께 적는다
