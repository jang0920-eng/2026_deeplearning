# 가상 스크리닝 — 필터 → 활성 예측 → 다양성 선별

ChEMBL 전체 화합물에서 도킹할 1,000개를 추리는 과정이다.
수치는 모두 실제 실행 결과이며, 각 단계의 스크립트 이름을 함께 적어 둔다.

## 깔때기 전체

| 단계 | 들어감 → 나옴 | 환경 | 도구 | 스크립트 |
|---|---|---|---|---|
| 1. 물리화학 필터 | 2,897,819 → 1,423,957 | 학교 리눅스 CPU | RDKit | `07_physchem_filter.py` |
| 2. ML 활성 예측 | 1,423,957 → 20,000 | 로컬 CPU 8스레드 | Morgan + RF | `08_ml_screen.py` |
| 3. 다양성 선별 | 10,000 → 1,000 | 로컬 CPU | sphere exclusion | `09_diversity_select.py` |
| 4. GNINA 도킹 | 1,000 → 약 100 | Colab T4 | GNINA | `11_dock_1000.ipynb` |
| 5. ADMET·용해도 | 약 100 → 15~30 | — | ADMET 예측 | (예정) |

단계마다 **다른 성격의 정보**를 쓴다. 1단계는 분자의 물리화학적 성질,
2단계는 알려진 CDK2 억제제와의 구조 유사성(학습된 패턴),
3단계는 후보들 사이의 구조적 중복, 4단계는 단백질 포켓과의 3차원 상호작용이다.
싼 계산으로 많이 걸러내고 비싼 계산을 적은 수에만 쓰는 것이 깔때기의 목적이다.

## 1단계 — 물리화학 필터

입력 `chembl_37_chemreps.txt.gz` 2,897,819개 → 통과 **1,423,957개** (49.1%).
염·혼합물은 탈락시키지 않고 가장 큰 조각만 남겨 계속 평가했다.

| 탈락 사유 | 제거 수 | 기준 |
|---|---|---|
| SMILES 파싱 실패 | 15 | 구조를 읽을 수 없음 |
| 무기 원소 포함 | 604 | 금속 착물 등 — 도킹 대상이 아님 |
| 크기 범위 밖 | 142,094 | 중원자 10 미만(조각) 또는 50 초과 |
| lead-like 위반 | 1,039,701 | MW > 450 또는 회전결합 > 7 |
| Lipinski 위반 | 149,073 | logP > 5, HBD > 5, HBA > 10 중 하나 |
| PAINS 구조 | 87,750 | 위양성을 자주 내는 구조 |
| 중복 구조 | 54,625 | 정규 SMILES 기준 동일 |

필터는 순서대로 적용했고 집계는 **처음 걸린 사유** 기준이다.
가장 많이 걸러낸 것은 lead-like(104만 개, 전체의 36%)로, ChEMBL 에 펩타이드·천연물 등
큰 분자가 많기 때문이다.

**lead-like 조건을 넣은 이유**: 도킹 소요 시간이 회전결합 수에 비례해 늘어나므로
평균 도킹 시간이 내려간다. 동시에 신약 개발 관점에서도 타당한데, 최적화 과정에서
분자량이 커지는 경향을 고려하면 출발 물질은 lead-like 영역에 두는 편이 유리하다.
계산 제약과 화학적 타당성이 같은 방향을 가리킨 선택이다.

**계획과의 차이**: 당초 1단계 출력을 약 50만 개로 예상했으나 실제로는 142만 개였다.
2단계 추론 대상이 약 3배로 늘었지만 최종 도킹 대상 1,000개는 그대로 유지했다.

## 2단계 — 활성 예측 모델 선정

### 비교한 조합 — 분자 표현 **3계열**

분자를 수에 담는 방식이 서로 다른 세 계열을 모두 넣었다.

| 계열 | 모델 | 표현 방식 | 수업 |
|---|---|---|---|
| **지문** | Morgan fingerprint (ECFP4, 2048 bit) | 부분구조를 비트로 센다 — **규칙이 고정** | baseline |
| **트랜스포머** | ChemBERTa-10M-MTR | 10M 분자, multi-task regression 사전학습 | W9 |
| | ChemBERTa-77M-MLM | 77M 분자, masked language modeling 사전학습 | W9 |
| **그래프** | Chemprop D-MPNN | 원자·결합을 노드·엣지로 보고 **메시지 전달로 표현을 학습** | W10 |

지문·트랜스포머는 표현을 뽑아 분류기(LogReg / RF) 2종에 넣었고,
D-MPNN 은 표현 학습과 분류를 한 네트워크에서 함께 한다.
사전학습 모델은 **frozen**(파인튜닝하지 않음)으로 쓰고 encoder 출력을
masked mean pooling 한 384차원 벡터를 썼다.

평가는 `scripts/eval_utils.py` 의 **같은 함수**로 했다.
hyperparameter 와 threshold 는 **val** 에서 고르고 **test 는 마지막에 한 번만** 평가했다.
scaler 는 train 에서만 fit 했다 (누출 방지).

### 결과 (scaffold split test 273개, 활성 159개)

| 모델 | 계열 | PR-AUC | ROC-AUC | precision | recall |
|---|---|---|---|---|---|
| **Morgan + RF** | 지문 | **0.8807** | **0.8231** | 0.7403 | 0.8428 |
| ChemBERTa-10M-MTR + RF | 트랜스포머 | 0.8637 | 0.7985 | 0.7000 | 0.8365 |
| **Chemprop D-MPNN** | **그래프** | **0.8577** | 0.8107 | 0.7288 | 0.8113 |
| ChemBERTa-10M-MTR + LogReg | 트랜스포머 | 0.8355 | 0.7875 | 0.7643 | 0.7547 |
| ChemBERTa-77M-MLM + RF | 트랜스포머 | 0.8262 | 0.7446 | 0.6309 | 0.9245 |
| Morgan + LogReg | 지문 | 0.7611 | 0.7345 | 0.7405 | 0.7358 |
| ChemBERTa-77M-MLM + LogReg | 트랜스포머 | 0.7400 | 0.6832 | 0.6962 | 0.6918 |

**채택: Morgan fingerprint + Random Forest** (PR-AUC 0.881).

### 결과에서 읽은 것

**표현을 학습하는 두 계열이 모두 고정된 지문에 졌다.**
트랜스포머 최고가 0.8637, 그래프가 0.8577, 지문+RF 가 0.8807 이다.
순위가 **지문 > 트랜스포머 > 그래프** 로 나왔고, 이 순서는 모델의 표현력 순서와 반대다.

학습 데이터가 2,721개로 작고, 활성 비율이 치우쳐 있으며, 화학적으로 몇 개 골격에
몰려 있다. **표현을 데이터에서 배우는 모델은 배울 데이터가 있어야 유리하다.**
이 규모에서는 부분 구조를 직접 세는 표현과 그것을 비선형으로 조합하는 트리 모델이
유리하다. 사전학습 임베딩의 장점(큰 데이터에서 배운 일반적 표현)도
파인튜닝 없이 frozen 으로 쓰면 충분히 발휘되지 않는다.

D-MPNN 은 사전학습 없이 2,176개만으로 표현을 처음부터 배워야 했는데도
ROC-AUC 0.8107 로 전체 2위다. 데이터가 더 있으면 순위가 바뀔 여지가 있다는
뜻이지만, **이 데이터에서는 그렇지 않았다는 것이 결론이다.**

→ `scripts/12_chemprop_compare.py`, `experiment/12_chemprop/`

### Chemprop 학습 조건

| 항목 | 값 |
|---|---|
| 버전 | Chemprop 2.3.1 / torch 2.15.0+cpu, 시드 42 고정 |
| 구조 | BondMessagePassing + MeanAggregation + BinaryClassificationFFN |
| 격자 | depth {3, 5} × dropout {0.0, 0.2}, hidden 300 — **4개** |
| 선택 | val AP 로 `depth 3, dropout 0.2` (val AP 0.7894) |
| early stopping | val_loss, patience 10, 최대 60 epoch → 23 epoch 에서 멈춤 |
| threshold | val 에서 F1 최대인 0.2099 |
| 소요 | 로컬 CPU 886초 (4개 설정 합계) |

격자를 4개로 제한한 것은 **계산 자원 제약에 맞춘 선택**이다. GPU 를 쓰지 않아
Colab 할당량을 도킹에만 쓸 수 있었다. 격자가 작으므로 "충분히 탐색했다"고는 쓰지 않는다.

**10M-MTR > 77M-MLM — 사전학습 데이터 양보다 학습 목표가 중요했다.**
두 ChemBERTa 는 구조가 완전히 동일하다 (hidden 384, layer 3, head 12,
vocab 600, 파라미터 3.43M). 다른 것은 사전학습 데이터 규모(1,000만 vs 7,700만)와
사전학습 목표(multi-task regression vs masked language modeling)뿐이다.
구조가 통제돼 있으므로 성능 차이를 **사전학습 목표의 차이**로 돌릴 수 있다.
분자 물성을 직접 맞히도록 학습한 MTR 쪽이 활성 예측에 더 쓸 만한 표현을 만들었다.

문헌에서 MTR 이 더 좋다고 보고된 것을 보고 골랐지만, **고른 뒤 같은 split 에서
직접 검증했다.** 문헌을 근거로 선택하고 끝내지 않았다는 점이 중요하다.

### ⚠ EF 를 모델 비교 지표로 쓸 수 없었다

EF(enrichment factor)는 가상 스크리닝의 표준 지표이지만 **이 test 에서는 쓸 수 없다.**
test 활성 비율이 58.2%이므로 EF 의 이론적 최대값은 1 / 0.582 = **1.717**이다.
상위를 전부 활성으로 맞혀도 이 값을 넘지 못하고, 실제로 RF 두 개가 천장에 붙었다
(EF 5% = 1.717). D-MPNN 도 EF 1% 에서 1.717 로 천장에 닿는다.
지표가 모델을 구분하지 못하는 상태다.

그래서 모델 비교는 PR-AUC·ROC-AUC 로 했다.
**지표를 그대로 쓰지 않고 적용 조건을 먼저 확인한 사례다.**

EF 자체는 활성 비율이 낮은 실제 스크리닝에서 의미가 있다.
그 조건을 만들어 측정한 결과가 아래 2단계 적용 결과에 있다.

## 2단계 적용 — 142만 개 활성 예측

스크립트: `scripts/08_ml_screen.py` → `experiment/08_ml_screen/`

모델은 위에서 채택한 Morgan + RF 를 그대로 쓰고, hyperparameter 도 05 단계에서
val 로 고른 값(`n_estimators=500, max_depth=None, min_samples_leaf=1`)을 유지했다.
여기서 다시 고르지 않았다.

**학습 데이터는 train+val 2,448개만 썼다. test 273개는 끝까지 제외했다.**
이유는 아래 농축 측정 때문이다.

| 예측 확률 | 분자 수 | 비율 |
|---|---|---|
| ≥ 0.5 | 154,536 | 10.85% |
| ≥ 0.7 | 9,076 | 0.64% |
| ≥ 0.9 | 920 | 0.065% |

- 점수 분포: 최소 0.000 / 중앙값 0.359 / 최대 1.000
- 상위 **20,000개**를 다음 단계로 넘겼다 (경계 점수 0.635)
- 상위 20,000위 안에 있던 **알려진 CDK2 분자 911개는 후보에서 제외**했다.
  라이브러리가 ChEMBL 전체이므로 학습에 쓴 분자가 그 안에 들어 있다.
  이들은 신규 후보가 아니다. 다만 순위는 `08_known_ranks.csv` 에 남겼다.
- 계산 시간: 로컬 CPU 8스레드로 60분 (초당 약 390개)

### EF 천장 문제를 푼 방법 — 라이브러리를 배경으로 한 농축

05 단계에서 EF 를 쓸 수 없었던 이유는 test 활성 비율이 58.2%로 너무 높아
천장이 1.717 이었기 때문이다. 그런데 스크리닝 모델을 train+val 로만 학습했으므로
**test 273개는 142만 개 라이브러리 안에 섞여 있는 미지의 분자**가 된다.
배경이 커지면서 활성 비율이 0.005% 수준으로 떨어지고, 상위 1% 기준 EF 의
이론적 최대값이 100 이 된다. 천장이 사라진 조건에서 측정한 결과다.

| 기준 | 라이브러리 안 test 활성 68개 중 | EF |
|---|---|---|
| 상위 0.1% (1,424개) | 8개 | **117.6** |
| 상위 1% (14,240개) | 26개 | **38.2** |
| 상위 5% (71,198개) | 39개 | **11.5** |

- test **활성** 분자의 순위 중앙값: 상위 **2.07%**
- test **비활성** 분자의 순위 중앙값: 상위 **40.12%**

scaffold split 이므로 이 68개의 골격은 학습에 전혀 쓰이지 않았다.
즉 처음 보는 골격의 활성 분자를 142만 개 중에서 상위로 끌어올렸다는 뜻이다.
(train·val 분자는 학습에 쓴 것이므로 상위에 몰리는 것이 당연하고,
 실제로 train 활성의 순위 중앙값은 상위 0.04%였다. 모델이 제대로 적용됐는지
 확인하는 양성 대조로만 쓰고 성능 근거로는 쓰지 않는다.)

### 1단계 필터가 알려진 활성 분자를 얼마나 남겼는가

|---|---|---|

도킹 시간을 줄이기 위해 감수한 손실이며, 그 크기를 실측해 둔 값이다.

## 3단계 다양성 선별 — 10,000 → 1,000

스크립트: `scripts/09_diversity_select.py` → `experiment/09_diversity/`

점수 상위 10,000개에서, 이미 고른 분자와 **Tanimoto 0.6 이상으로 겹치지 않는**
분자를 점수 높은 순서로 1,000개 골랐다 (sphere exclusion).
기준을 완화하지 않고 1,000개를 채웠으며, 유사체로 제외된 분자는 2,556개다.

| 항목 | 다양성 선별 1,000개 | 점수 상위 1,000개 (비교용) |
|---|---|---|
| 서로 다른 Murcko 골격 수 | **775** | 426 |
| 집합 내 최근접 유사도 평균 | **0.526** | 0.788 |

점수만 보고 1,000개를 뽑으면 골격이 426종으로 줄어든다.
같은 도킹 시간(약 16시간)으로 **1.8배 넓은 화학 공간**을 보기 위한 선택이다.

**다양성의 대가도 숫자로 남긴다.**
선택된 분자의 RF 점수는 0.760 ~ 1.000 이고, ML 순위로는 4,363위까지 내려갔다.
점수를 일부 포기하고 구조적 다양성을 얻은 것이다.

- 평균 분자량 383.3, 평균 logP 2.96, 평균 회전결합 4.83개, 평균 중원자 27.0개
- 회전결합 평균이 4.83개로 02 단계 속도 실측 대상과 같은 범위이므로
  개당 59초 가정이 유지된다 → 약 16시간

**왜 Butina 클러스터링이 아닌가**: Butina 는 클러스터 중심 분자를 뽑는데,
중심은 점수와 무관하게 결정되므로 클러스터 안에서 가장 유망한 분자를 놓칠 수 있다.
sphere exclusion 은 점수 우선순위를 유지한 채 유사 구조만 배제한다.
10,000 × 10,000 거리 행렬(5천만 쌍)을 만들지 않아 메모리도 적게 쓰고,
난수를 쓰지 않아 결과가 항상 같다.

## 도킹 입력 리간드 3D 구조

스크립트: `scripts/10_ligand_prep.py` → `experiment/10_ligands/`

1,000개 중 **996개** 생성 성공 (MMFF 힘장 없음 3개, conformer 생성 실패 1개).

- `ETKDGv3`, `randomSeed = 42` — 같은 입력이면 항상 같은 좌표
- MMFF94s, `maxIters = 2000`, **수렴 코드 확인** (한 번 더 돌려도 수렴 안 하면 제외)
- 수소를 뗀 SDF — 03 단계 redocking B(RMSD 0.56 Å)와 같은 입력 형식
- 생성한 SDF 를 저장소에 커밋했다. ETKDG 는 시드를 고정해도 RDKit 버전이 다르면
  좌표가 달라질 수 있으므로, 도킹 입력 파일 자체를 고정해 둔 것이다.

이 단계를 따로 둔 이유는 02 단계에서 Vina 점수가 +1.10 kcal/mol(결합 불성립)인
분자가 나왔기 때문이다. 박스가 작아서라고 추정했으나 16/20/24 Å 비교에서
차이가 0.13 kcal/mol 뿐이라 기각됐고, 실제 원인은 시드를 고정하지 않은 ETKDG 와
수렴을 확인하지 않은 MMFF 최적화, 즉 3D 구조 생성 품질이었다.
