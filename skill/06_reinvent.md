# 6단계 — REINVENT 로 탐색 범위 확장

보고서 §9 "탐색 범위" 와 과제 명세 **보고서 필수 포함 4번**(분자 구조 탐색 범위를
넓힌 경우 그 방법 설명) 에 대응하는 단계다.

**이 문서의 §3 판정 기준은 생성 결과를 보기 전에 정해 적었다** (2026-11-17).
결과는 §5 에 나중에 채운다.

---

## 1. 왜 REINVENT 인가

1~3단계는 ChEMBL 290만 개라는 **이미 존재하는 집합 안에서** 추렸다.
깔때기가 좁히기만 하므로, 그 집합에 없는 구조는 끝까지 나오지 않는다.
REINVENT 는 SMILES 를 token 열로 보고 다음 token 을 예측하는 LSTM 이라,
학습 분포에서 **새 SMILES 를 만들어 낸다**. 탐색 범위를 넓히는 방향이 반대다.

모델 계열도 하나 늘어난다. 2단계에서 비교한 것은 지문(Morgan), 트랜스포머
(ChemBERTa), 그래프(Chemprop D-MPNN) 세 계열이었고, 여기에 **순환신경망
(LSTM)** 이 더해져 **4계열**이 된다. 수업 진행과도 맞는다 (W08 RNN →
W09 Transformer → W10 graph).

## 2. 무엇을 쓰는가

`reinvent.prior` — REINVENT4 가 배포하는 사전학습 가중치다.

| 항목 | 값 | 확인 방법 |
|---|---|---|
| 출처 | Zenodo `10.5281/zenodo.15641297` (REINVENT4 priors) | 수업 자료 W08 p30 에 적힌 DOI |
| 크기 | 23,226,277 바이트 (23.2 MB) | `ls` — 수업 자료의 "23.2 MB" 와 일치 |
| sha256 | `b6513ec6dbc54c87ea45cdbf9b4aaefadd7652548b74175366b27f12ec5732fe` | `sha256sum` |
| 사전학습 데이터 | **ChEMBL 25** | 체크포인트 `metadata.origina_data_source` |
| 구조 | Embedding 256 → LSTM 3층 × hidden 512 → Linear | 체크포인트 `network_params` |
| vocabulary | 34 토큰 (`$`=EOS, `^`=BOS, `C` `c` `Br` `[nH]` …) | 체크포인트 `vocabulary._tokens` |
| 파라미터 수 | 5,805,602 | 재구현 모델에 적재 후 계산 |
| 최대 길이 | 256 token | 체크포인트 `max_sequence_length` |

재학습은 하지 않는다. 가중치를 불러와 sampling 만 한다.

### REINVENT4 패키지를 설치하지 않은 이유

`scripts/15_reinvent_sample.py` 는 추론 경로(Embedding → LSTM → Linear →
softmax → sampling)를 **순수 torch 로 다시 구현**하고 체크포인트의
`network` state dict 를 그대로 적재한다. `load_state_dict(strict=True)` 가
**All keys matched successfully** 로 통과하므로 구조가 원본과 같다.

설치하지 않은 이유는 두 가지다.

1. **5단계 환경을 깨뜨리면 안 된다.** `chemprop-env` 는 admet-ai 2.0.1 /
   chemprop 2.3.1 / torch 2.15.0+cpu 로 맞춰져 있고 5단계 ADMET 이 여기 의존한다.
   REINVENT4 를 `pip install` 하면 torch·numpy 버전을 끌어내릴 수 있다.
2. **내려받은 pickle 을 그대로 열지 않기 위해서다.** `torch.load` 는 기본값이
   `weights_only=True` 이고, 이 체크포인트는 `reinvent.models.meta_data.ModelMetaData`
   를 요구해 안전 모드로는 열리지 않는다. `weights_only=False` 는 임의 코드 실행
   위험이 있다. 그래서 제한 Unpickler 로 읽고, 텐서는 zip 안의 storage 바이트에서
   `torch.frombuffer` 로 직접 만든다. 실행되는 코드는 우리 스크립트 안의 것뿐이다.

결과적으로 **추가 설치가 0개**이고, 1~5단계 환경을 하나도 건드리지 않는다.

(`02_docking.md` 의 회전결합 회귀 기준). Colab 할당량에 부담이 없고, 996개와
**같은 GNINA 설정·같은 박스**를 써서 점수를 직접 비교할 수 있다.

### 신규성을 유사도로 판정하지 않는 이유

중복 제거는 **canonical SMILES 정확 일치**로만 한다. Tanimoto 유사도는
**보고만 하고 탈락 기준으로 쓰지 않는다.** 지문이 비슷하다고 활성이 비슷한 것이
아니고, 그 반대도 아니다. `CLAUDE.md` 의 "embedding 이 비슷하다고 활성이 비슷한
것이 아니다" 와 같은 이유다. 유사도 분포는 "얼마나 기존 집합 밖으로 나갔는가"를
보여주는 **기술 통계**로만 싣는다.

## 4. 한계 (먼저 적는다)

1. **prior 는 CDK2 를 모른다.** ChEMBL 25 전체로 사전학습했을 뿐이고 CDK2 활성으로
   fine-tuning 이나 강화학습(RL)을 하지 않았다. 따라서 생성 분자에는 **표적 특이성이
   없다.** 표적 쪽 정보는 전부 뒤에 붙는 2단계 ML 모델과 4단계 도킹이 넣는다.
   수업 자료 W08 p30 의 경고와 같은 내용이다 — **생성 확률 / QED ≠ 표적 결합 친화도.**
2. **RL 로 최적화하지 않았다.** REINVENT 본래 용법은 scoring function 을 정해
   prior 를 agent 로 강화학습하는 것이다. 여기서는 sampling 만 한다. 과제 요구인
   "탐색 범위를 넓힌 방법"에는 해당하지만, REINVENT 의 전부는 아니다.
3. **사전학습 데이터에 평가 분자가 들어 있는지 확인할 수 없다.** ChEMBL 25 로
   학습했고 우리 CDK2 활성 데이터도 ChEMBL 에서 받았으므로, 생성 분자가 사실상
   기억된 학습 분자일 수 있다. 정확 일치는 제거하지만 그것으로 전부 걸러지지 않는다.
   이 한계는 2단계 ChemBERTa 와 같은 성격이다.
4. **생성 분자는 합성 가능성을 검증하지 않았다.** 실제 구할 수 있는 화합물이
   아니므로 1~3단계 후보와 성격이 다르다. 보고서에서 둘을 같은 줄에 놓지 않는다.

제거했지만 그것으로 전부 걸러지지 않는다.

### Tanimoto 최근접 유사도 (보고용, 탈락 기준 아님)

신규 **9,609개** 각각에 대해 기준 집합 중 최대 Tanimoto 를 구했다.

| 기준 집합 | 중앙값 | 평균 | p90 | 최대 | ≥0.4 | ≥0.7 |
|---|---|---|---|---|---|---|
| 3단계 선별 1,000개 | 0.237 | 0.242 | 0.305 | 0.615 | 109 | **0** |
| CDK2 활성 분자 | 0.264 | 0.270 | 0.339 | **0.814** | 234 | **2** |

중앙값이 0.24~0.26 이고 p90 이 0.34 를 넘지 않는다. 기존 집합과 지문이 크게 다른
영역에서 분자가 나왔다는 뜻이고, "탐색 범위를 넓혔다"는 주장의 근거가 된다.
다만 **유사도가 낮은 것이 활성이 좋다는 뜻은 아니다.**

**⚠ 정정** — 이 문서의 첫 판에는 "≥0.7 이 하나도 없다"고 적었는데 **틀렸다.**
스모크 실행(198개)의 값을 본 실행 값으로 착각해 적은 것이다. 실제로는 CDK2 활성
분자와 **0.7 이상인 생성 분자가 2개** 있다.

| gen_id | vs 활성 | vs 3단계 선별 | 비고 |
|---|---|---|---|
| GEN05662 | 0.814 | 0.266 | 설폰산 + 안트라퀴논 골격 |
| GEN06451 | 0.745 | 0.243 | 이소프레노이드 사슬 |

**두 분자 모두 1단계 물리화학 필터에서 탈락해 ML 점수 단계로 가지 않았다**
(`08_library_scores.csv` 에 없다). 정확 일치 기준으로는 "신규"지만 알려진 활성
분자와 지문이 매우 가깝고, 필터가 그것과 무관하게 걸러 냈다. 정확 일치만으로
신규성을 판정하는 것의 한계를 보여주는 사례이므로 그대로 싣는다.

**이것이 이 단계의 가장 중요한 결과다. 생성 분자의 ML 점수가 기존 후보보다

**예상한 결과이고, §4 한계 1 을 그대로 확인한 것이다.** prior 는 ChEMBL 전체로
사전학습했을 뿐 CDK2 를 모르므로 표적 특이성이 없다. 생성이 탐색 범위를 넓히는
것은 맞지만, **넓힌 영역의 평균 품질은 기존 집합의 상위권보다 낮다.**
깔때기를 ChEMBL 에서 시작한 선택이 틀리지 않았다는 근거이기도 하다.

⚠ `08_ml_screen.py` 가 출력한 EF 지표는 전부 NaN 이다. 생성 분자에는 활성 label 이
없어 농축도를 계산할 대상이 없기 때문이다. **지표 계산 실패가 아니라 정의상 해당
없음**이므로 보고서에 EF 로 싣지 않는다.

### 원래 계획과 다른 점 (숨기지 않고 적는다)

`docs/HANDOFF.md` 깔때기 표의 6단계는 **"15~30 → 신규 구조"**, 즉 5단계를 통과한
최종 후보를 **출발점으로 확장**하는 그림이었다. 실제로 한 것은 prior 의
**무조건부 sampling** 이라 특정 후보에서 출발하지 않는다. 수업 W08 실습과 같은
방식이고 과제 요구("탐색 범위를 넓힌 방법 설명")는 충족하지만 계획과는 다르다.

후보에서 출발하는 확장은 같은 Zenodo 레코드의 `libinvent.prior`(scaffold 치환) 또는
`mol2mol_similarity.prior`(유사 구조 생성) 가 필요하다. 둘 다 80~95 MB 트랜스포머
(encoder–decoder) 라 LSTM 보다 재구현이 무겁다. **4·5단계가 끝나 최종 후보가
확정된 뒤에 판단한다.** 위 ML 점수 결과는 그 선택을 뒷받침한다 — 표적 정보를
넣지 않은 생성은 점수가 낮으므로, 활성 분자를 조건으로 주는 쪽이 유리할 수 있다.

## 6. 도킹 준비 (11/17 완료, 실행은 996개 뒤에)

**3D 구조** — 996개와 **같은 스크립트·같은 시드**로 만들었다
(`10_ligand_prep.py`, ETKDGv3 randomSeed=42, MMFF94s maxIters=2000 수렴 확인).
**50개 전부 성공**했다 (996개 때는 1,000개 중 4개가 실패했다).

**dock_id 충돌을 막았다.** `08_top_candidates.csv` 의 `rank` 열에는 동점이 4쌍
있어서 그대로 id 로 쓰면 50개 중 4개가 겹친다. Drive `poses/` 는 dock_id 로
파일을 쌓으므로 겹치면 **포즈가 조용히 덮어써진다.** 점수 내림차순 + gen_id
오름차순으로 결정적 순번을 매겨 `G001`~`G050` 을 부여했고, 기존 `C0001`~`C1000`
과 충돌이 0건임을 검증했다.

**노트북** — `11_dock_1000.ipynb` 에서 파생했고 **경로·제목·세션 예산만** 바꿨다.
박스(center 92.37/80.29/−47.95, size 16.1×15.8×16.5), exhaustiveness 8,
num_modes 9, seed 1 은 **한 글자도 바꾸지 않았다.** 996개와 점수를 직접 비교하려면
같은 조건이어야 한다. 치환 후 이 값들이 그대로인지 검증했다.

출력은 `experiment/17_docking_generated/` 로 분리해 4단계 결과를 건드리지 않는다.
50개 × 약 78초 = 약 1시간이므로 `MINUTES_BUDGET = 90` 으로 잡았다.

⚠ **996개 도킹을 끝낸 뒤에 돌린다.** Colab 할당량은 4단계가 우선이다.

**결과를 보기 전에 정해 두는 것**: 생성 분자의 2단계 ML 점수는 996개보다
낮았다(중앙값 0.342 vs 0.806). 도킹 점수도 낮게 나올 수 있고, ML 점수와 다른
순위를 줄 수도 있다. **어느 쪽으로 나오든 그대로 싣는다.** 생성 분자를 최종 후보에
넣을지는 도킹 결과를 보고 정하되, 넣는다면 **1~5단계 후보와 같은 줄에 놓지 않고
출처를 구분해 적는다** (§4 한계 4 — 합성 가능성을 검증하지 않았다).
