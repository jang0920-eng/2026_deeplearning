## 2026-10-31 (금) — 타겟 확정, 활성 데이터 수집

**한 일**
타겟을 CDK2(CHEMBL301)로 확정하고 단백질 구조 3RPR을 선정.
ChEMBL에서 활성 데이터 5,367건을 받아 정제해 2,724개 분자의 데이터셋 구축.
(상세: `01_data.md`)

**결정 1 — 질환을 "유방암"이 아니라 "CDK4/6 억제제 내성 유방암"으로 좁힘**
단순히 유방암 치료제라고 하면 이미 승인된 CDK4/6 억제제로 충분하지 않냐는 반문이 가능하다.
반면 내성은 실제로 미충족 수요가 남아 있는 영역이며, 그 기전이 cyclin E-CDK2 활성화이므로
CDK2를 표적으로 삼는 근거가 분명해진다. 표적 선정의 타당성을 확보하기 위한 선택이다.

**결정 2 — IC50 / Ki / Kd 세 지표를 통합**
IC50만으로는 3,692건에 그쳐 학습 데이터가 부족했다.
세 지표는 측정 방식이 달라 엄밀히 같은 척도가 아니지만,
데이터 부족으로 인한 과적합 위험이 척도 불일치로 인한 오차보다 크다고 판단했다.
이 한계는 보고서에 명시한다.

**결정 3 — 부등호 데이터 1,727건(32%) 제외**
`>10000 nM` 형태는 정확한 수치가 아니어서 회귀 학습에 부적합하다.
다만 확실한 비활성 사례이므로 폐기하지 않고 보관한다.
모델 성능이 부족할 경우 비활성 라벨로 재활용해 약 4,400건까지 확대할 수 있다.

**결정 4 — 구조는 3RPR 선정, 6INL·5L2W 탈락**
6INL은 결손 구간 148–162가 포켓 잔기 Asp145 바로 뒤에 위치해 결합 부위 신뢰도가 떨어진다.
5L2W는 해상도 2.80 Å로 부족하고 cyclin E가 동반되어 불필요하게 복잡하다.
다만 5L2W의 dinaciclib은 임상 화합물이므로 최종 후보와의 비교 대상으로 보관한다.

## 2026-11-04 (수) — GNINA 설치, 도킹 속도 실측

**한 일**
Colab에 GNINA v1.3.3 설치(conda 대신 GitHub 릴리스 바이너리, Drive에 저장해 재사용).
3RPR 수용체 준비(물 217개·리간드 25Z 제거, pH 7.4 수소 부가) 및 redocking용 25Z 추출.
리간드 20개로 도킹 속도 측정. GitHub 저장소 `2026_deeplearning` 생성.
(상세: `02_docking.md`)

**결정 1 — CNN 채점을 켠 채로 유지**
CNN을 켰을 때 59.0초/개, 껐을 때 60.6초/개로 유의미한 차이가 없었다.
즉 병목은 CNN 채점이 아니라 CPU에서 수행되는 도킹 탐색(Monte Carlo)이며,
무료 Colab은 vCPU가 2코어뿐이라 GPU 성능과 무관하게 여기서 제한된다.
CNN을 켜도 추가 비용이 없으면서 CNNscore라는 독립적인 평가 지표를 얻으므로 켠 채로 간다.

**결정 2 — 도킹 대상을 3,000개에서 1,000개로 축소**
실측 59초/개를 적용하면 3,000개는 약 49시간으로, 세션이 수시로 끊기는
무료 Colab에서는 현실성이 없다. 1,000개면 약 15시간이라 나흘에 분할 처리할 수 있다.
줄어든 만큼은 ML 활성 예측 단계의 통과 기준을 높여 보완한다.
계산 자원의 한계를 인지하고 파이프라인을 재설계한 사례로 보고서에 기술한다.

**결정 3 — 물리화학 필터에 lead-like 조건 추가 (회전결합 ≤ 7, MW ≤ 450)**
도킹 소요 시간은 리간드의 회전결합 수에 비례해 증가하므로
이 조건은 평균 도킹 시간을 낮추는 효과가 있다.
동시에 신약 개발 관점에서도 타당한데, 최적화 과정에서 분자량이 증가하는 경향을 고려하면
출발 물질은 lead-like 영역에 두는 편이 유리하기 때문이다.
계산 제약과 화학적 타당성이 같은 방향을 가리킨 선택이다.

**확인 필요**
속도 측정 20개 중 Vina 점수가 +1.10 kcal/mol로 나온 사례가 있다.
양수는 결합이 성립하지 않았음을 뜻하며, 중원자 31개 분자가
16 Å 도킹 박스를 벗어났을 가능성이 있다. redocking 검증 시 함께 확인한다.

## 2026-11-05 (수) — redocking 검증, 박스 점검, 모델 비교

**한 일**
도킹 검증(redocking) A/B를 모두 통과했고, 양수 점수의 원인을 실측으로 확인했다.
scaffold split을 만들고 활성 예측 모델 6조합을 같은 split에서 비교했다.
(상세: `02_docking.md`, `03_screening.md`)

**결정 1 — 양수 도킹 점수의 원인은 박스가 아니라 3D 구조 생성이었다**
`CHEMBL271182`를 16 / 20 / 24 Å 박스로 재도킹하니 −8.80 / −8.93 / −8.91 로
차이가 0.13 kcal/mol 뿐이었다. "박스가 작아서"라는 추정은 기각된다.
실제 원인은 속도 측정 노트북에서 ETKDG 시드를 고정하지 않았고 MMFF 최적화가
기본 200회에 수렴 확인도 없었던 것이다. 뒤틀린 구조가 단백질과 충돌했다.
→ 박스는 16 Å 유지, 리간드 준비 코드를 고쳐 시드를 고정한다.
추정으로 설정을 바꾸지 않고 실측으로 확인한 사례이므로 보고서에 쓴다.

**결정 2 — RMSD 는 `rdMolAlign.CalcRMS` 로 계산한다**
`GetBestRMS`는 두 분자를 정렬한 뒤 재므로 "제자리를 재현했는가"를 묻는
도킹 검증에는 맞지 않는다. `CalcRMS`는 정렬 없이 대칭만 고려한다.
결과: A(결정 좌표 입력) 0.60 Å, B(SMILES에서 새 3D) 0.56 Å로 기준 2.0 Å을 크게 밑돌았다.
B가 A보다 좋아 "출발 구조를 알려줬다"는 반박이 성립하지 않는다.

**결정 3 — 무작위 분할 대신 scaffold split**
CDK2 억제제는 같은 골격의 유사체가 몰려 있어 무작위로 나누면 test 성능이 부풀려진다.
Murcko scaffold 1,173종 기준으로 80/10/10 분할했고 split 간 골격 교집합은 전부 0이다.
val·test는 전부 단일 분자 골격이므로 test의 모든 분자가 처음 보는 골격이다.

**결정 4 — 활성 예측 모델은 Morgan + RF 채택**
PR-AUC 기준 Morgan+RF 0.881 > ChemBERTa-10M-MTR+RF 0.864 > ... > 77M-MLM+LogReg 0.740.
두 ChemBERTa는 구조가 완전히 동일(hidden 384, layer 3, head 12, 3.43M)하고
사전학습 데이터 규모와 목표만 다르므로, 10M-MTR이 더 나은 것을 **사전학습 목표의
차이**로 돌릴 수 있다. 데이터 양(7,700만)보다 학습 목표가 중요했던 사례다.
문헌을 보고 고른 뒤 같은 split에서 직접 검증했다는 점이 핵심이다.

**결정 5 — EF를 모델 비교 지표에서 뺀다**
test 활성 비율이 58.2%라 EF의 이론적 최대값이 1 / 0.582 = 1.717이다.
상위를 전부 맞혀도 넘을 수 없는 값이고 실제로 RF 두 개가 천장에 붙었다.
지표가 모델을 구분하지 못하므로 비교는 PR-AUC·ROC-AUC로 한다.
지표를 그대로 쓰지 않고 적용 조건을 확인한 사례다.

   Vina 기준 최선값이 아니다** (평균 1.71 kcal/mol, 최대 3.60 차이).
   도킹 결과에 pose 1 값과 전체 최소값을 둘 다 기록한다.

추가하면 **지문 / 트랜스포머 / 그래프 세 계열**을 같은 scaffold split 에서 비교한 것이 된다.
05 단계와 같은 `eval_utils` 를 쓰고, hyperparameter 는 val AP 로 고르고 test 는 한 번만
평가한다. 격자는 4개(depth 3·5 × dropout 0·0.2)로 제한했다 — 로컬 CPU 제약에 맞춘 것이고
그 이유를 summary 에 적는다. GPU 를 쓰지 않으므로 Colab 할당량은 도킹에만 쓴다.

**결정 2 — ADMET 도구는 ADMET-AI 로 한다** (`skill/04_admet.md`)
SwissADME·pkCSM 은 웹 폼이라 모델 버전을 고정할 수 없다. 재현성 20점이 걸려 있고
교수가 재현을 시도하므로 **pip 로 버전을 고정해 로컬에서 돌리는 쪽**을 택했다.
ADMET-AI 2.0.1 은 chemprop >= 2.2.2 를 요구하므로 결정 1 의 환경(`chemprop-env`)을
그대로 쓴다. 예측 모델이 chemprop D-MPNN 이라 GNN 계열 설명과도 이어진다.

**결정 3 — ADMET 판정 기준을 도킹 결과 전에 확정했다**
결과를 본 뒤에 문턱값을 정하면 원하는 분자가 남도록 맞춘 셈이 된다.
hERG · AMES · DILI 예측 확률 > 0.5 를 탈락 기준으로 **미리** 정해 문서에 적었다.
0.5 는 이진 분류 기본 결정 경계이고 임의로 조정하지 않았다.
흡수·분포·대사는 탈락시키지 않고 기록만 한다 (제형·구조 최적화로 개선되는 영역).

⚠ **BBB 는 높을 필요가 없다.** 적응증이 HR+/HER2− 유방암이므로 뇌가 표적 장기가 아니다.
"BBB 가 낮아서 나쁘다"고 쓰지 않는다.

**정정 — 1단계 출력이 계획의 약 50만 개가 아니라 142만 개다**
숨기지 않고 `07_filter` 요약에 차이와 영향을 적었다. 필터 기준(Lipinski, PAINS,
lead-like)은 미리 정해 그대로 적용했고 숫자를 맞추려고 조건을 추가하지 않았다.
통과율 49.1% 가 예상(약 30%)보다 높은 이유는 ChEMBL 이 애초에 생물활성이 보고된
분자 모음이라 이미 drug-like 에 가깝기 때문이다. 최종 도킹 대상 1,000개는 그대로다.

**추가 (11/14 새벽) — ADMET 탈락 기준을 확률 0.5 에서 승인 약물 백분위로 바꿨다**

경위를 그대로 적는다. 순서가 중요하다.

1. 처음에는 이진 분류 기본 결정 경계인 **p > 0.5** 를 탈락 기준으로 정해 적었다.
2. 도킹을 기다리지 않고 3단계 선별 분자 **5개로 시험 실행**했다.
   5개 전부 탈락했다 (DILI 5/5, hERG 4/5).
3. 문턱값을 그냥 완화하는 대신, **0.5 가 의미 있는 기준인지 실측했다.**
   ADMET-AI 가 함께 제공하는 승인 약물 2,845개에 같은 기준을 적용한 결과:
   **DILI 44.3%, hERG 37.2%, AMES 20.9% 가 p > 0.5 다.**
   0.5 로 자르면 시판 중인 약의 44%가 간독성으로 탈락한다. 기준이 잘못됐다.
   TDC 학습 데이터가 독성 보고 분자에 치우쳐 예측 확률 자체가 높게 나온다.
4. 기준을 **승인 약물 분포에서의 백분위 > 90** 으로 바꿨다.
   "이미 시판 중인 약의 90%보다 나쁘다"는 뜻이고 해석이 가능하다.

**이것이 결과에 맞춘 조정이 아닌 이유**: 판단 근거는 우리 분자 5개의 결과가 아니라
승인 약물 2,845개의 분포이고, 그 자료는 이 프로젝트와 무관하게 패키지에 들어 있다.
또한 최종 후보를 정하는 **도킹 결과는 아직 없고**, 시험에 쓴 5개는 도킹 순위가 아니라
파일 앞에서 순서대로 가져온 것이다.

**다만 숨길 일이 아니므로** 백분위 90 에 생물학적 근거가 없다는 점을 명시하고,
`scripts/13_admet.py` 가 **백분위 80 / 90 / 95 각각의 통과 개수를 함께 출력**하게 했다.
결과가 문턱값 하나에 좌우되지 않는다는 것을 보고서에 그대로 보인다.

**시험 실행에서 함께 확인된 것**
- 예측 출력은 항목 52개(TDC 41 + 물리화학 11) + 백분위 52개 = **104개 컬럼**
- 백분위 접미사는 `drugbank_approved_percentile` — 버전에 따라 달라질 수 있어
  코드가 실행 시점에 찾는다. `molecular_weight` 처럼 밑줄이 든 항목이 있어
  첫 밑줄로 자르면 틀린다 (실제로 한 번 틀렸다)
- 한국어 Windows 콘솔(cp949)에서 admet-ai 내부 lightning 진행바가 `•`(U+2022)를
  출력하다 `UnicodeEncodeError` 로 죽는다. **예측이 끝난 뒤 진행바 정리 단계에서**
  터지므로 원인을 찾기 어렵다. 출력 스트림을 utf-8 로 바꿔 해결했다.
  교수가 Windows 에서 재현할 때 같은 문제를 만날 수 있어 코드에 주석으로 남겼다.
