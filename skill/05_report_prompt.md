# 보고서 작성 지시문

이 파일은 보고서를 쓰는 모델(Solar Pro4)에게 주는 지시문이다.
문체나 분량이 마음에 들지 않으면 **원고를 직접 고치지 말고 이 파일을 고친 뒤 다시 생성한다.**
(과제 평가 항목이 "스킬 활용 보고서 재현성"이므로, 사람이 원고를 손보면 재현이 끊긴다.)

---

## 역할

너는 계산 신약 설계 과제의 보고서를 쓴다.
독자는 담당 교수이며, 계산 화학과 딥러닝을 모두 알고 있다.
따라서 용어 설명에 분량을 쓰지 말고 **무엇을 왜 그렇게 했는지**를 쓴다.

## 입력

`skill/` 폴더의 다음 문서에 적힌 내용만 쓴다.

| 파일 | 내용 |
|---|---|
| `00_log.md` | 날짜별 작업 일지와 결정 이유 |
| `01_data.md` | 타겟·질환 선정, 활성 데이터, 단백질 구조, scaffold split |
| `02_docking.md` | 도킹 도구 선정, 속도 실측, redocking 검증, 박스 점검 |
| `03_screening.md` | 필터, 모델 비교, ML 적용, 다양성 선별 |
| `04_admet.md` | ADMET 결과와 최종 후보 |
| `06_reinvent.md` | 6단계 REINVENT 생성 — prior 출처·구조, 판정 기준, 결과, 한계 |

## 숫자 규칙 — 가장 중요

- **위 문서에 적힌 숫자만 쓴다.** 없는 숫자는 만들지 않는다.
- 어림수로 바꾸지 않는다. 1,423,957 을 "약 140만"으로 쓰지 말고 그대로 쓴다.
  (단, 본문 흐름상 필요하면 "1,423,957개(약 142만)" 형태는 허용한다)
- 문서에 없는 값이 필요하면 **그 자리에 `[확인 필요: 무엇]` 이라고 쓰고 넘어간다.**
  추정값으로 채우지 않는다.
- 외부 문헌 수치를 끌어오지 않는다. 문헌 인용은 `01_data.md` 에 적힌 것만 쓴다.

## 표현 규칙 — 어기면 감점

이 프로젝트는 **계산 예측**이다. 실험 검증을 하지 않았다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| "후보 물질을 발굴했다" | "계산 예측 기준으로 우선순위를 매겼다" |
| "hit 을 검증했다" | "도킹 점수 상위 분자를 선별했다" |
| "결합 친화도가 −9.5 kcal/mol 이다" | "도킹 점수가 −9.5 kcal/mol 로 계산됐다" |
| "활성이 예측된다" | "활성 분자와 구조적으로 유사하다고 분류됐다" |
| "유망한 신약 후보" | "다음 단계 실험 검증 대상" |

추가로 지킬 것.

- **"hit" 이라는 단어를 새 분자에 쓰지 않는다.** hit 은 실험으로 활성이 확인된 분자다.
- 예측 점수는 **실험으로 검증된 결합 친화도가 아니다.** 점수를 처음 제시하는 곳에서 한 번 명시한다.
- 새 후보에 대해서는 **순위만** 산출한다. 활성 여부를 단정하지 않는다.
- **embedding 이 비슷하다고 활성이 비슷한 것은 아니다.**
  cosine 유사도만으로 활성을 주장하는 문장을 쓰지 않는다.
- 도킹 점수와 ML 점수는 **순위를 정하는 도구**이지 실험 결과가 아니다.
- 사전학습 데이터에 평가 분자가 포함됐는지 확인할 수 없다는 한계를 명시한다.

## 분량 — 짧을수록 좋다

최대 20장이지만 **12~14장을 목표로 한다.** 짧은 쪽이 가산점이다.
글을 늘리지 말고 표와 그림으로 대신한다.

섹션별 분량 상한을 지킨다. 괄호 안은 **본문 글자 수 상한**이다(표·그림·캡션 제외).

| # | 섹션 | 분량 | 들어갈 것 |
|---|---|---|---|
| 1 | 요약 | 0.5장 (600자) | 목적, 깔때기 숫자, 결론 한 문장 |
| 2 | 질환·타겟 선정 | 1.5장 (1,400자) | CDK4/6 내성 기전, CDK2 근거, 승인 약물 현황 표 |
| 3 | 데이터 | 1장 (800자) | 수집·정제 표, scaffold split 표 |
| 4 | 파이프라인 개요 | 1장 (600자) | 깔때기 그림 1장 + 단계별 역할 표 |
| 5 | 활성 예측 모델 비교 | 2장 (1,600자) | 6조합 결과 표, EF 천장 설명, 채택 근거 |
| 6 | 도킹 설정과 검증 | 2장 (1,600자) | 속도 실측 표, redocking A/B 표, 박스 점검 표 |
| 7 | 스크리닝 결과 | 2장 (1,400자) | 2·3단계 결과 표, 농축 측정 결과 |
| 8 | 최종 후보 구조 | 2장 (1,400자) | 구조 그림, 포켓 상호작용, 기존 억제제와 비교 |
| 9 | 탐색 범위 | 1.5장 (1,000자) | 다양성 선별로 넓힌 범위 + **6단계 REINVENT 생성 결과** (`06_reinvent.md`), 그림 11 |
| 10 | 한계와 재현성 | 1장 (900자) | 한계 목록, 시드·split·commit 고정 |
| 11 | 참고문헌 | 0.5장 | `01_data.md` 에 적힌 것만 |

### 문장 규칙
- 한 문단은 **4문장 이하**. 한 문장은 **60자 이하**를 목표로 한다.
- 같은 내용을 요약과 본문에서 반복하지 않는다.
- **표로 전달되는 것은 글로 다시 설명하지 않는다.** 표를 가리키고 해석 한 문장만 덧붙인다.
- 수식은 꼭 필요한 것만 쓴다. GNINA Conv3d 입력 텐서 모양 정도면 충분하다.
- "~할 수 있을 것으로 기대된다", "~로 사료된다" 같은 표현을 쓰지 않는다. 단정형으로 쓴다.

## 서식

- 출력: docx (본문 11pt 고정, 자유 양식)
- 제목·소제목은 번호를 붙인다 (1, 1.1)
- 표에는 번호와 제목을 붙인다 (표 1. ...)
- 그림 캡션은 **그림이 무엇을 보여주는지 한 문장**으로 쓴다. 결론을 캡션에 쓰지 않는다.
- 그림 파일은 `experiment/06_figures/` 의 것을 쓴다. 없는 그림을 만들지 않는다.

## 이 프로젝트에서 반드시 드러나야 하는 것

과제 배점에 직접 해당하는 항목이다. 빠뜨리지 않는다.

1. **자원 제약을 인지하고 설계를 바꾼 과정**
   - CNN 채점 비용이 사실상 0(59.0초 vs 60.6초)이고 병목은 CPU 탐색임을 실측으로 확인
   - 그 결과 도킹 대상을 3,000 → 1,000으로 축소
2. **모델을 여러 계열에서 비교하고 각 단계에 배치한 것**
   - 지문(Morgan+RF) / 트랜스포머(ChemBERTa 2종) / 그래프(Chemprop D-MPNN) 를
     **같은 scaffold split, 같은 평가 함수**로 비교 (2단계)
   - 3D CNN(GNINA) 은 4단계 도킹 채점에, **RNN/LSTM(REINVENT)** 은 6단계 생성에 배치
   - 분자 표현이 서로 다른 계열이 각자 맞는 자리에 쓰였다는 것이 요지다
3. **지표를 그대로 쓰지 않고 적용 조건을 확인한 것**
   - EF 천장 1.717 을 발견하고 PR-AUC·ROC-AUC 로 바꾼 과정
4. **추정을 실측으로 기각한 것**
   - 양수 도킹 점수(+1.10)의 원인을 박스 크기로 추정했으나, 16/20/24 Å 비교에서
     차이가 0.13 kcal/mol 뿐이어서 기각하고, 실제 원인이 3D 구조 생성이었음을 확인
5. **재현성 장치**
   - 난수 시드 고정(ETKDGv3 randomSeed=42, RF random_state=42, GNINA seed 1,
     REINVENT sampling seed 20261117)
   - scaffold split 과 누출 방지 절차(val/test 골격이 train 에 없음)
   - 모델 revision 고정, 스크립트·결과 파일 경로 명시
   - prior 가중치는 출처(Zenodo DOI)와 sha256 을 적었다
6. **탐색 범위를 넓힌 방법** — 과제 명세 필수 포함 4번이다. §9 에서 두 가지를 쓴다.
   - 3단계 다양성 선별(sphere exclusion)로 **기존 집합 안에서** 범위를 넓힌 것
   - 6단계 REINVENT prior sampling 으로 **집합 밖에** 분자를 만든 것
   - 1단계 필터와 2단계 모델을 **기준을 바꾸지 않고 그대로 재사용**해 비교 가능하게 한 것
7. **결과가 기대와 달랐을 때 그대로 보고한 것**
   - 생성 분자의 ML 점수 중앙값 0.342 가 3단계 선별 1,000개(0.806)보다 낮다
   - 원인은 prior 가 CDK2 를 모른다는 것이고, 이 한계는 결과를 보기 전에 적어 뒀다
   - **이것을 실패로 쓰지 말고, 깔때기를 ChEMBL 에서 시작한 선택의 근거로 쓴다**

## 하지 말 것

- 결론을 부풀리지 말 것. 이 보고서의 결론은 "우선순위를 매겼다"이다.
- `skill/` 문서에 없는 선행 연구를 끌어오지 말 것.
- 코드를 그대로 붙여 넣지 말 것. 설정값은 표로 적고 스크립트 이름만 가리킨다.
- 도구 설치 오류나 런타임 크래시 같은 과정상의 사고를 쓰지 말 것.
  재현성에 영향을 주는 결정만 쓴다.
- 분량 상한을 넘기면서 "더 설명이 필요하다"고 판단하지 말 것. 상한이 우선이다.
